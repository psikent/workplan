# 甘特条颜色编码改用备注，状态退出甘特视觉编码

甘特条原本按状态着色(frappe-gantt 惯例)。2026-09 起:甘特条颜色 =「备注」(key `remarks`)选项的管理员配色(未设置或归档值为中性灰),负责人冲突警示色保持最高优先级覆盖;状态不再有任何甘特视觉编码——条色与按状态的进度暗条全部移除,已取消/已完成的计划在甘特上与待开始不可区分,出口是状态筛选器与默认关闭的可选「状态」文本属性。驱动原因:备注分类(值班/自动化/网络安全)才是排期画面需要一眼分辨的维度;状态是过程属性,由列表徽章、筛选器、工作台统计承载已足够。

## Considered Options

- **保留状态色,备注用第二视觉通道(条缘描边/纹理)(被拒)**:双通道并存画面语义过载,甘特条尺寸下描边/纹理辨识度差。
- **颜色跟随字段做成可配置(被拒)**:投机性设计,当前只有按备注着色一种诉求;固定绑定 `remarks` key(同 owner/ticket 约定),语义固化为词汇表「Gantt Color Coding (甘特颜色编码)」。

## Consequences

- 甘特上无法目视区分已取消/已完成计划;需要时用状态筛选器排除,或在甘特属性中主动勾选「状态」文本。
- 进度暗条随状态编码一并取消(所有条无暗条),`gantt-<status>` CSS 与按状态 progress 注入删除。
- 选项颜色是通用数据能力(所有单选字段 schema 均有 color 列,环境配置包随包迁移),但设置页仅对备注暴露编辑、甘特仅消费备注;将来更换编码字段时数据层零改动。
- 见 `.scratch/gantt-color-by-remarks/spec.md`。
