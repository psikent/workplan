# 确立工作计划排序体系的基础原则

Type: grilling
Status: resolved
Blocked by:

## Question

完整的工作计划排序体系应覆盖哪些对象和场景，采用怎样的主序、比较语义、权威边界与兼容方向？

## Answer

- 最终产物是完整需求规格、决策地图和实施票据；未获明确批准前不开发。
- 排序对象统一称为“工作计划”。覆盖工作计划页、甘特图、工作台计划分组、提醒、列表与搜索 API、XLS 导出和重复计划实例；JSON 备份物理行序不在范围内。
- 使用清晰流水线：入选 → 分组 → 场景主序 → 统一稳定兜底 → 分页或导出。不同场景可以有不同业务主序，但不能各自发明并列规则。
- 不保留含义模糊的全局人工排名，也不提供工作计划拖动排名。工作计划 `sortOrder` 及 `/work-plans/reorder` 进入退役路径；自定义字段定义自身的排序不受影响。
- Schedule Order（排期顺序）固定为：开始时间升序 → 结束时间降序 → 创建时间升序 → ID 升序。重复规则只是来源，不构成优先级。
- 工作台区块保持：今日提醒 → 今日新开工 → 今日继续开工 → 接下来的计划。今日新开工包括当日开始且已完成的计划、排除已取消；其余两个计划分组只收有效计划。计划组内使用排期顺序。
- 提醒先按类型组织，检修单提醒优先于作业计划提交提醒；同类提醒中的工作计划使用排期顺序。
- 用户最多指定五个排序字段，逐项比较；每个字段只服从自己的升降方向，全部相等后始终回退到排期顺序，不整体反转兜底顺序。
- 可排序内置字段：工作内容、状态、开始时间、结束时间、持续时长、创建时间、更新时间。不可排序：说明、重复来源、版本号、内部 ID、工作负责人账号。
- 可排序自定义字段：短文本、数字、布尔、日期、日期时间、单选、URL。长文本和多选不可排序。
- 文本使用面向中文用户、忽略大小写并识别数字的自然顺序；数字按数值，日期按日历日，日期时间按绝对时间点，持续时长按时间差，单选按管理员配置顺序，布尔升序为未勾选后已勾选。
- 空值、空白文本和失效选项统一视为缺失值，升降序都置后；重复或不支持的排序字段返回明确参数错误，不静默忽略。
- 工作计划页提供独立排序面板，默认排期顺序；表格和甘特图共享完全相同的结果。
- 排序偏好优先级为 URL → 当前账户的浏览器偏好 → 默认排期顺序。页面偏好不改变工作台或提醒；从该页发起的 XLS 导出沿用该页查询顺序。
- 服务端是最终排序权威。普通列表、搜索、筛选和导出复用同一查询引擎；前端不再二次排序。
- 新查询使用带完整排序位置和最终 ID 的不透明游标并返回准确总数；旧 offset 仅作兼容。列表是实时视图，刷新后允许行随数据变化重新定位，不提供跨请求历史快照。
- 工作台统计改为服务端准确聚合，不再由最多 500 条列表推算。导出在单次数据库读事务中重新执行完整查询，不受页面分页限制。
- 绝对时间按时间点排序；今天、本周、本月等日历边界统一按 Asia/Shanghai 解释。
- 工作计划 `sortOrder` 先经过明确兼容窗口停止输出和拒绝重排；核实本地脚本及自动化无依赖后再执行数据库删列迁移，旧数值不迁移。
