# 16 — 生产启用并完成十四天兼容观察

Type: task
Status: ready-for-human
Blocked by: 15
Spec: ../spec.md
Scope: 经单独授权的生产发布、监控、兼容调用方协调与观察记录

## Background

本票包含生产状态改变和持续 14 天观察，不能仅凭代码合并自动结案。执行前需要用户明确授权，并遵循生产发布技能和仓库运行手册。

## Work

1. 发布前核对分支/提交、生产服务、备份、磁盘空间、迁移版本、健康检查和回退包；不得读取或打印密钥。
2. 分阶段启用统一查询和 Web 排序，保留旧 offset API、数据库 `sort_order` 列和重排墓碑路由。
3. 发布后验证登录、工作计划页面、表格/甘特、工作台、提醒、Viewer、XLS、健康与就绪端点。
4. 连续观察 14 个自然日：查询延迟、5xx、数据库忙、导出失败、结果错误报告和墓碑调用。
5. 若墓碑被调用，定位并迁移调用方，将连续零调用窗口重新从零计算；若正确性或预算回归，按规格回退并停止计时。
6. 每日或按约定频率追加脱敏证据；完成时记录观察起止时间、提交、生产版本、零调用证明和最终放行结论。

## Acceptance

- 新查询与 Web 排序连续 14 天满足性能和正确性门槛。
- 排序/分页相关 5xx、数据库忙、已确认结果错误和墓碑调用均为零。
- 旧 offset API 与 JSON 备份回退接缝在观察期保持可用。
- 用户明确确认可以进入最终数据库清理；否则票据保持未完成。
