# 定义排序面板与偏好状态

Type: grilling
Status: resolved
Blocked by: 01

## Question

工作计划页的排序面板应怎样表达默认排期顺序、多字段优先级和升降方向；URL 与账户级浏览器偏好的格式和覆盖规则是什么；字段被归档、配置失效、请求加载或失败时怎样降级并反馈；桌面端、移动端、键盘和只读账户分别需要哪些交互保证？

## Answer

- 工作计划页提供独立的“排序”面板。没有显式排序项时显示“排期顺序（默认）”；用户可添加、删除和调整最多五个互不重复的排序字段，并分别选择升序或降序。面板从上到下表示比较优先级，清空全部排序项即恢复排期顺序。
- 表格与甘特图共享同一查询结果和排序状态，不允许任一视图在客户端再次排序。切换视图、调整时间范围或打开工作计划详情不重置排序。
- URL 使用单个可分享参数，规范格式为 `sort=<field>:<direction>,<field>:<direction>`，例如 `sort=title:asc,custom.risk:desc`；字段名使用查询契约中的稳定键，方向只能是 `asc` 或 `desc`。默认排期顺序不写 `sort` 参数。
- 偏好优先级固定为：合法 URL 参数 → 当前账户在当前浏览器中的偏好 → 默认排期顺序。浏览器偏好按稳定账户 ID 隔离并带版本号，退出或切换账户不能复用另一账户的排序；URL 只覆盖本次导航，不反向覆盖已保存偏好，用户在页面主动修改后才保存新偏好并更新 URL。
- URL 排序整体不合法时，不发送无效查询：回退到排期顺序并显示可见、可关闭的说明。浏览器偏好中的未知、重复、不支持或已归档字段逐项移除，保留仍合法的项目、写回修复后的偏好并提示一次；若没有合法项目则回退到排期顺序。直接调用 API 时不做降级，返回明确参数错误。
- 排序请求加载期间保留上一次成功结果，并在面板和结果区域显示刷新状态；正在提交的同一排序操作不可重复触发。请求失败时保留上一次成功结果、排序选择和页面上下文，显示内联错误与重试入口，不伪装为已成功应用。
- 桌面端使用就近弹出面板，移动端使用不超出视口的面板或抽屉；两者提供相同能力。字段调整不得只依赖拖动，必须有可聚焦的上移、下移、移除和方向控件，具备明确标签、焦点顺序和状态反馈。
- Administrator、Editor 与 Viewer 都能使用排序，因为排序不修改业务数据；Token-only Account 没有 Web 工作台，因此不涉及浏览器偏好。
- 从工作计划页发起的 XLS 导出携带页面当前已经成功应用的查询与排序；页面仍在失败或待首次成功状态时不得把未生效排序冒充为导出顺序。
