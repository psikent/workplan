# 明确工作台成员与日期边界

Type: grilling
Status: resolved
Blocked by: 01

## Question

如何把已确认的工作台分组原则落实为无重叠、无边界歧义的成员判定：工作计划时间区间和日历区间是否采用半开区间，午夜结束、跨日、手动完成、当日取消、未来取消及第七个工作日边界分别归入哪里；提醒区块与三个计划区块之间是否允许同一计划重复出现？

## Answer

- 工作计划时间范围统一采用半开区间 `[startAt, endAt)`：开始时刻属于计划，结束时刻不属于计划。所有绝对时间先按时间点比较；需要判断“今天”或本地日期时统一转换到 `Asia/Shanghai`。
- 本地日历日同样表示为半开区间 `[当日 00:00, 次日 00:00)`。工作计划与某日相交，当且仅当 `startAt < 次日 00:00` 且 `endAt > 当日 00:00`。因此恰好在当日 00:00 结束的计划不属于当日，恰好在当日 00:00 开始的计划属于当日。
- 三个工作台计划区块使用同一个求值时刻和同一个“今天”，并且彼此互斥：
  - 今日新开工：开始本地日等于今天且有效状态不是已取消；即使该计划已在今天完成，仍保留在本区块。
  - 今日继续开工：开始本地日早于今天、时间范围与今天相交，且有效状态既不是已完成也不是已取消。跨日计划在今天结束但结束时刻尚未到达时属于本区块；到达结束时刻后退出。
  - 接下来的计划：开始本地日晚于今天、不晚于从今天向后数的第七个工作日，且有效状态既不是已完成也不是已取消。窗口包含中间经过的周末，终点当天包含在内。
- 手动状态覆盖自动状态：当日或未来手动取消的计划不进入任何计划区块；手动完成的计划只在其开始日为今天时进入“今日新开工”，不进入另外两个区块。
- “今日提醒”是独立关注面，不参加三个计划区块的互斥判定。同一工作计划可以同时出现在今日提醒和恰好一个计划区块中，因为提醒表达“今天需要注意”，计划区块表达“今天或近期如何排期”。
- 每个计划区块内部均使用排期顺序；成员判定先于排序执行。
