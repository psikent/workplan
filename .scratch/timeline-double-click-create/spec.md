# Spec: 时间轴双击日期格新建工作计划

> Status: **已完成** — 规格已定稿（/grill-with-docs 共识，2026-08-20）；票据 01–04 全部 done，代码与测试已落地（`GanttTimeline.tsx` dblclick + 「双击新建工作计划」悬停提示；`WorkPlansPage.tsx` 日期预填与不可见保存反馈），2026-08-22 核实通过。2026-08-31 修复周末列被 frappe-gantt 周末高亮覆盖层拦截双击/悬停的回归（`issues/05`）。

## Goal

用户在工作计划页面的周视图或月视图中，可通过双击时间轴日期网格背景，打开已经预填目标日期的新建工作计划抽屉，从当前浏览位置快速安排该日工作。

本功能沿用现有 **Work Plan（工作计划）**，不引入单独的“任务”领域对象。

## Terms

见 `CONTEXT.md`：**Work Plan**、**Automatic Status**、**Manual Status Override**、**Recurring Rule**、**Custom Field**。

本文中的“日期格”是时间轴表头下方，某个可见日期列与某个可见行带相交形成的视觉网格区域。纵向所在行没有业务含义；日期只由横向所在日期列确定。无可见工作计划时，空态网格正文视为一条可交互的虚拟行。

## Background facts

- 时间轴位于 `/work-plans` 的 `WorkPlansPage`，右侧由 `GanttTimeline` 基于 Frappe Gantt 渲染；周/月视图都使用一天一列。
- 当前唯一显式新建入口是页面顶部“新建工作计划”按钮；它打开 `WorkPlanDrawer`。
- 新建抽屉当前默认今天 `08:30–18:00`，状态为 Automatic Status，自定义字段使用字段定义中的默认值，默认不启用 Recurring Rule。
- 甘特条单击会打开现有工作计划；甘特条的移动和两端拉伸由应用自行处理。
- 当前无可见工作计划时，甘特挂载容器会被清空并显示纯空态，因此实现本需求时必须保留可定位日期的网格正文。
- 现有创建接口和持久化流程已满足本功能；本需求不要求新增服务端领域对象或创建 API。

## Requirements

### R1 双击触发范围

- 周视图和月视图均支持本功能。
- 仅双击**日期表头下方的网格背景**触发新建。
- 根据鼠标横向位置确定目标日期；纵向所在工作计划行不得影响新建内容，也不得建立与该行的关联。
- 以下区域不得触发新建：
  - 日期数字及月份表头；
  - 甘特条及其拖拽、拉伸区域；
  - 时间轴工具栏、按钮、弹出层及其他控件。
- 单击网格背景不执行任何操作，不引入持久或临时的日期选中状态。
- 双击触发必须与拖拽、拉伸判定互斥，不能因一次拖拽或拉伸误建工作计划。

### R2 新建抽屉与默认值

- 成功识别双击后，复用现有 `WorkPlanDrawer` 打开新建流程；双击本身不向服务端写入数据。
- 开始时间预填为目标日期 `08:30`，结束时间预填为同日 `18:00`。
- 目标日期按**浏览器本地日历日期**解释，与现有时间轴日期渲染、日期输入及整日排程语义一致。
- 除日期外，其余默认值完全沿用顶部“新建工作计划”入口：
  - Automatic Status；
  - 各 Custom Field 的现有默认值；
  - 默认不启用 Recurring Rule；
  - 现有校验、保存、错误反馈和取消行为。
- 过去、今天、未来以及周六、周日均允许新建；保存后的有效状态继续按既有 Automatic Status 规则派生。

### R3 空态和筛选无结果

- 当前时间范围没有工作计划，或搜索、状态、自定义字段筛选导致没有可见工作计划时，日期网格仍须可见并可双击。
- 空态说明可以继续显示，但不得遮挡日期定位、悬停反馈或双击事件。
- 空态网格必须保持与当前周/月范围一致的一天一列映射，包括范围首日和末日。

### R4 已有甘特条的双击行为

- 双击已有甘特条不得创建新工作计划。
- 双击甘特条的最终效果与单击一次相同：只打开该条已有工作计划的编辑抽屉一次。
- 不得出现抽屉先打开又关闭、重复打开或背景遮罩接收第二次点击的闪烁行为。
- 现有甘特条单击编辑、整日移动、左端拉伸、右端拉伸和悬停提示行为必须保持不变。

### R5 悬停反馈与可发现性

- 鼠标进入可双击的新建区域时，仅高亮指针所在的日期格，不高亮整条日期列。
- 同时提供可见提示文案：`双击新建工作计划`。
- 鼠标进入甘特条、拖拽手柄、日期表头或其他不可新建区域时，不显示该高亮和提示。
- 高亮与提示不得拦截双击，不得影响甘特条悬停提示或列表行与甘特行的悬停同步。

### R6 保存后的视图和反馈

- 用户可在抽屉中修改预填日期及其他字段。
- 保存后保持当前时间轴范围、搜索词、状态筛选和自定义字段筛选，不自动跳转日期，也不自动重置筛选。
- 若新工作计划在当前范围和筛选条件下可见，沿用正常的创建成功反馈。
- 若用户修改日期到当前范围之外，或新计划不符合当前筛选条件，须明确提示：工作计划已创建，但在当前时间范围或筛选条件下不可见。

### R7 入口与设备范围

- 顶部“新建工作计划”按钮必须保留，继续作为键盘和触屏用户的创建入口。
- 本期不新增触屏长按、单击选中日期、键盘日期网格操作或其他双击等价手势。
- 权限沿用现有工作计划创建权限；不为此功能新增账户角色或授权规则。

## Testing requirements

- 为日期坐标映射增加组件测试，覆盖：
  - 周视图和月视图；
  - 范围首日、范围中间日期和范围末日；
  - 自适应列宽与月视图最小列宽；
  - 浏览器本地日期转换。
- 为双击交互增加渲染测试，覆盖：
  - 双击网格背景只打开一次新建抽屉并预填目标日 `08:30–18:00`；
  - 单击网格背景无操作；
  - 日期表头双击无操作；
  - 甘特条双击只编辑已有工作计划一次；
  - 拖拽、拉伸不触发新建；
  - 空数据和筛选无结果时仍能双击新建。
- 为悬停反馈增加测试：仅目标日期格高亮并显示 `双击新建工作计划`；离开或进入不可新建区域后清除。
- 为保存反馈增加页面测试：计划可见时正常提示；因日期范围或筛选不可见时提示不可见原因，并保留当前范围与筛选。
- 既有 `GanttTimeline`、`WorkPlanDrawer` 和 `WorkPlansPage` 测试保持通过。

## Acceptance criteria

1. 用户在周视图或月视图双击任意非甘特条日期网格背景，抽屉打开一次，并将对应浏览器本地日期预填为 `08:30–18:00`。
2. 新建抽屉的状态、Custom Field 默认值、Recurring Rule 默认值、校验和保存流程与顶部新建入口一致；双击前不产生任何持久化记录。
3. 日期表头、甘特条、拖拽手柄和工具控件不触发新建；网格单击无操作。
4. 双击甘特条只打开已有工作计划一次；现有单击编辑、移动、拉伸和悬停行为无回归。
5. 没有可见工作计划时仍显示正确的周/月日期网格，范围首尾日期都可双击新建。
6. 悬停可新建区域时，仅当前日期格高亮并显示“`双击新建工作计划`”；不可新建区域不显示。
7. 过去、今天、未来及周末日期均可使用；有效状态按现有 Automatic Status 派生。
8. 保存后不改变当前时间范围或筛选；若计划不可见，明确提示其因当前时间范围或筛选条件未显示。
9. 不新增服务端创建 API、领域对象、触屏长按或日期网格键盘交互。
10. Web 类型检查和相关测试全部通过。

## Out of scope

- 自动保存无标题或默认标题的工作计划。
- 新的“任务”类型、任务与工作计划之间的映射或新的服务端创建接口。
- 日期表头双击、网格单击选中、触屏长按和键盘网格导航。
- 自动跳转到保存后的日期、自动清除筛选或改变当前周/月视图。
- 修改工作计划的默认工作时段、Automatic Status 规则、Recurring Rule 或 Custom Field 默认值。
