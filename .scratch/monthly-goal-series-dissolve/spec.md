# 月目标重复系列解散

## 目标

在保留现有“停止生成”能力的同时，允许用户从一个月目标实例发起“解散重复系列”：保留已被使用的实例为普通月目标，永久删除未被使用的纯自动实例与系列规则。

## 领域语义

- **停止生成**：仅将系列置为已停止，不再补生成实例；系列规则与全部实例继续保留。
- **解散重复系列**：删除系列规则；发起实例与有使用痕迹的实例转为普通月目标；仅删除未使用的纯自动实例。
- 发起实例始终保留。
- 实例满足任一条件即视为有使用痕迹并强制保留：`updated_at !== created_at`、当前已归档、当前已关联工作计划。曾编辑、归档后恢复、关联后解绑都会因更新时间变化而保留。
- 保留实例清空 `series_id` 与 `occurrence_key`，其余业务字段保持不变；删除实例不可恢复。
- 活跃和已停止系列均可解散。

## 用户流程

1. 用户点击某个系列实例的重复徽标，系列管理对话框记录该实例为发起目标。
2. 用户点击“解散重复系列”，前端读取预览。
3. 预览将实例分为“保留为普通月目标”与“永久删除”，展示原因与保留/删除/关联数量；保护实例不可改选。
4. 用户输入发起目标的完整名称后，才能点击“解散并删除”。
5. 成功后系列对话框关闭，保留实例不再显示重复徽标，删除实例消失，并提示保留与删除数量。
6. 若预览后系列、实例或关联状态变化，操作整体中止，刷新预览并清空确认输入。

## API

### 预览

`GET /api/v1/monthly-goal-series/:id/dissolve-preview?keepGoalId=<uuid>`

返回系列版本、发起目标、逐实例动作与原因、统计以及 `snapshotToken`。动作是 `retain` 或 `delete`；保留原因可包含 `selected`、`edited`、`archived`、`linked`、`completed`。

### 执行

`POST /api/v1/monthly-goal-series/:id/dissolve`

请求体：

```json
{
  "keepGoalId": "uuid",
  "snapshotToken": "sha256",
  "confirmationTitle": "发起目标完整名称"
}
```

成功返回 `{ "retainedCount": number, "deletedCount": number }`。

`snapshotToken` 对系列版本/状态及所有实例的分类相关字段生成稳定哈希。执行时在事务内重新计算；不匹配返回现有 `409 VERSION_CONFLICT`。确认名称错误或发起目标不属于该系列返回 422；资源不存在返回 404。

## 原子操作

服务端在单个 SQLite 事务中：

1. 重新读取系列和实例，验证快照、发起目标及确认名称。
2. 删除纯自动实例。
3. 将全部保留实例转为普通月目标，并递增版本与更新时间。
4. 删除系列记录。

任何一步失败都不产生部分修改。权限沿用月目标系列现有管理员/编辑者权限；不新增数据库迁移，不改变普通月目标与现有停止 API。

## 验收

- 发起项、曾编辑/归档/关联的实例保留并去除系列属性，纯自动实例删除。
- 活跃与已停止系列都可解散；现有“停止生成”行为不变。
- 预览、名称确认、并发冲突与事务回滚有自动化覆盖。
- Web/Server/Contracts 专项与全量测试、类型检查、构建、浏览器流程及 `git diff --check` 全部通过。

## 范围外

- 撤销、回收站或恢复已删除实例。
- 在解散预览中覆盖保护规则并强制删除保护实例。
- 改变系列生成、规则编辑、导入导出或普通月目标删除语义。
- 新增 ADR 或数据库迁移。
