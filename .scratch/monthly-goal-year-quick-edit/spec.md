# 待实现规格：月目标年度快速编辑

## 目标

在月目标页右上角增加“快速编辑”入口，以一个年份为单位查看和编辑月目标：

- 表格横轴为所选年份的 1–12 月。
- 纵轴每行对应一个月目标名称。
- 单元格勾选表示该名称在该月存在至少一个未归档的 Monthly Goal。
- 用户可以一次完成全年新增、归档、恢复和重命名，再统一保存。

本功能是现有 Monthly Goal 实例的批量编辑视图，不引入独立的“年度目标行”实体。

## 已确认的产品决策

1. 快速编辑继承月目标页当前选择的年份，并在弹窗内允许切换年份。
2. 点击入口后使用全屏弹窗，而不是独立路由或普通居中弹窗。
3. 行字段对应现有“目标名称” `title`；详细“说明” `description` 不进入快速编辑。
4. 打开某年时，所有普通、重复系列和已归档实例都参与聚合；没有任何实例时显示一行空白。
5. 同名目标按去除首尾空格后的精确文本合并，大小写仍有区别；表格内不允许两个同名行。
6. 同名且同月存在多个实例时，一个勾选框代表整组；归档、恢复和重命名统一作用于该组。
7. 取消勾选采用可恢复的归档，不永久删除；重新勾选优先恢复已有归档实例。
8. 全年都已归档的名称仍显示为空勾选行，用户可以在快速编辑中恢复。
9. 修改已有行名称会更新该年该组全部实例，包括已归档和系列实例；不影响其他年份或系列模板。
10. 工作计划关联始终保留；快速编辑新建的实例默认不关联计划。
11. 新增行必须填写名称并至少勾选一个月份；未操作的纯空白占位行可以忽略。
12. 只有未保存的新行可以通过减号移除；已有行不能整行永久删除。
13. 所有修改保留在弹窗草稿中，点击“保存”后整批提交。
14. 未保存时关闭弹窗或切换年份，先确认是否放弃草稿。
15. 保存成功后关闭弹窗，月目标页切换到刚保存的年份，月份保持原选择。
16. 整批保存全有或全无；发生并发冲突时保留草稿，用户确认后才能重新载入最新数据。
17. 窄屏使用横向滚动，并固定左侧目标名称列。

## 领域边界

- 沿用 `CONTEXT.md` 中的 **Monthly Goal**、**Goal-Plan Link** 与 **Goal Recurrence**。
- “快速编辑行”只是界面从 Monthly Goal 实例推导出的临时分组，不是新的领域对象，也不持久化独立顺序或模板。
- Goal Recurrence 已生成的实例保持可独立编辑；快速编辑不会修改重复规则、系列模板、起止周期或生成范围。
- 新勾选一个原本没有实例的月份时，即使该行包含系列实例，也创建普通 Monthly Goal，不推断或扩展任何重复规则。
- 这些规则是可逆的界面与批量写入设计，不满足新增 ADR 的必要条件；`CONTEXT.md` 与 `docs/adr/` 均无需修改。

## 当前实现事实

- `GET /api/v1/monthly-goals` 已支持只传 `year` 并通过 `includeArchived=true` 返回该年全部实例。
- Monthly Goal 具有 `id/title/description/year/month/archivedAt/version/linkedWorkPlan/seriesId/occurrenceKey/createdAt/updatedAt`。
- 当前数据库只对 `(series_id, occurrence_key)` 建唯一索引；普通目标允许同名、同月重复，因此快速编辑必须显式处理实例组。
- 单项更新已经使用 `version` 乐观锁；当前没有年度批量写入接口。
- 归档不会解除 Goal-Plan Link，系列实例也允许单独编辑或归档。

## R1 — 入口与全屏弹窗

- 在月目标页右上角 `header-actions` 中增加次级按钮“快速编辑”，位置在“显示已归档”和“新建月目标”之前；附图只作为该入口位置参考。
- 按钮使用表格类图标并提供明确的可访问名称“快速编辑月目标”。
- 点击后打开全屏、模态的年度编辑器；标题为“年度快速编辑”，包含年份选择器、关闭按钮、表格、加号、取消和保存。
- 初始年份取月目标页当前 `year`；弹窗切换年份不改变父页面，只有保存成功后才把父页面年份更新为保存年份。
- 弹窗加载 `GET /monthly-goals?year=<year>&includeArchived=true`，独立展示加载失败和重试状态。

## R2 — 行与单元格推导

定义 `normalizedTitle = title.trim()`，按区分大小写的 `normalizedTitle` 聚合该年实例：

- 每个名称形成一行，已有行携带 `originalTitle = normalizedTitle`。
- 行显示名称使用去除首尾空格后的文本。
- 行顺序按组内最早 `createdAt` 升序；相同时间再按名称稳定排序。
- 新行携带 `originalTitle = null` 并追加到末尾。
- 无已有行时自动放置一个空白新行；用户移除最后一个新行后仍保留一个空白占位行。
- 已有行即使 12 个月都没有活跃实例也继续显示。

每个“行 × 月份”单元格的初始状态：

- 至少一个同组实例 `archivedAt === null` 时勾选。
- 没有活跃实例时不勾选，无论该月是没有实例还是只有已归档实例。
- 同一单元格同时存在活跃与已归档实例时仍显示为勾选。

## R3 — 编辑语义

保存时以初始勾选状态与最终草稿状态比较：

- `勾选 → 未勾选`：归档该单元格全部活跃实例，已有归档实例保持归档。
- `未勾选 → 勾选`：若存在归档实例，恢复该单元格全部归档实例；若完全没有实例，创建一个普通 Monthly Goal。
- 状态未变化：不改变该单元格各实例原有的归档状态。因此“活跃与归档并存”的历史组在未触碰时不会被意外全部恢复。
- 同一草稿内先取消再重新勾选、最终状态等于初始状态时视为无状态变更。

名称编辑：

- 已有行名称变化时，重命名该 `originalTitle` 在所选年份的全部实例，包括活跃、已归档、普通与系列实例。
- 重命名只改变 `title`；`description`、`year/month`、`work_plan_id`、`series_id`、`occurrence_key` 保持不变。
- 新建实例使用最终行名称、`description: ""`、`workPlanId: null`，且 `seriesId/occurrenceKey` 为空。
- 一个现有实例同时发生重命名和归档状态变化时，只执行一次更新并只递增一次 `version`。

## R4 — 草稿校验与行操作

- 目标名称沿用现有契约：`trim()` 后长度 1–200。
- 最终行名称按 `trim()` 后的区分大小写文本唯一；重复时在对应行显示错误并阻止保存。
- `activeMonths` 只允许不重复的整数 1–12，并按升序提交。
- 新行填写名称后必须至少勾选一个月份；新行勾选月份后必须填写名称。
- 完全空白且没有勾选月份的新占位行不提交，也不触发校验错误。
- 已有行允许 12 个月均不勾选，因为它代表全年已归档的实例组。
- 加号每次在末尾新增一行；减号只出现在尚未保存的新行上，移除该草稿行不写服务器。
- 保存按钮在加载中、保存中、存在校验错误或没有任何有效变更时禁用。

## R5 — 批量接口

复用现有年度 GET；新增：

`PUT /api/v1/monthly-goals/quick-edit`

请求体：

```json
{
  "year": 2026,
  "baseline": [
    { "id": "uuid", "version": 1 }
  ],
  "rows": [
    {
      "originalTitle": "原目标名称",
      "title": "最终目标名称",
      "activeMonths": [1, 2, 8]
    },
    {
      "originalTitle": null,
      "title": "新目标名称",
      "activeMonths": [9, 10]
    }
  ]
}
```

共享契约新增并导出请求/响应 schema 与 TypeScript 类型。契约要求：

- `year` 使用现有 2000–2100 范围。
- `baseline` 中 ID 唯一、版本为正整数。
- 已有行 `originalTitle` 唯一；新行使用 `null`。
- 最终 `title` 规范化后唯一。
- 新行至少一个 `activeMonths`；已有行允许空数组。
- 月份值唯一且为 1–12。

成功响应：

```json
{
  "createdCount": 2,
  "updatedCount": 4,
  "goals": []
}
```

`goals` 为保存后该年包含归档项的完整 `MonthlyGoal[]`；`updatedCount` 统计实际改变标题或归档状态的既有实例数，每个实例最多计一次。

## R6 — 服务端事务与并发

服务端在一个 SQLite transaction 内完成：

1. 读取该年全部活跃与已归档实例。
2. 将当前 `{id, version}` 集合与请求 `baseline` 做顺序无关的精确比较。
3. 任一实例新增、删除、缺失或版本变化时抛出现有 `409 VERSION_CONFLICT`，事务不写入。
4. 按当前快照的规范化标题捕获每个已有组的实例 ID；要求每个当前组在请求中恰好出现一次，且每个非空 `originalTitle` 都能匹配当前组。
5. 验证最终名称唯一，并据初始/最终单元格状态计算每个实例的唯一更新和需要创建的月份。
6. 按捕获的 ID 更新，保证两个已有行互换名称时不会串组；组合标题与归档变更后每个实例只递增一次版本。
7. 创建缺失月份的普通实例。
8. 返回保存后的年度完整列表与计数。

任何业务校验失败返回现有 422 输入错误；任何并发基线失败返回 409。权限沿用普通 Monthly Goal 路由：Administrator、Editor 和 Token-only Editor 都可调用，不新增管理员限制。

## R7 — 保存、冲突与响应式行为

- 点击保存只发送非空占位行，并携带打开/重新载入该年份时取得的完整 `id + version` 基线。
- 保存成功后刷新所有 `monthly-goals`、`work-plans` 和 `monthly-goal-series` 相关查询，显示成功提示，关闭弹窗并更新父页面年份；父页面月份不变。
- 普通 API 错误保留草稿并显示表单错误。
- 409 时显示“数据已变化，请重新载入后重试”和“重新载入”按钮；不自动覆盖草稿。
- 点击重新载入时再次确认会放弃未保存修改；确认后读取最新年度数据并清除错误。
- 关闭按钮、取消、遮罩点击、Escape 和切换年份都复用同一脏数据确认逻辑。
- 表格容器横向滚动；表头和左侧名称列使用 sticky 定位，12 个勾选列保持足够点击面积。
- 每个复选框具有“<目标名称或第 N 行>，<月份> 月”的可访问名称；全屏容器使用 `role="dialog"` 与 `aria-modal="true"`。

## R8 — 测试要求

### Contracts / Server

- 契约拒绝非法年份、重复 baseline ID、空名称、重复最终名称、重复/越界月份和无月份的新行。
- 创建一个或多个月份，字段默认值正确。
- 归档活跃实例、恢复归档实例、同名同月多实例整组操作。
- 同一单元格活跃/归档混合且状态未变化时保持原样。
- 重命名覆盖该年全部活跃/归档/系列实例，但不影响其他年份、说明、关联和系列模板。
- 已有系列行新增缺失月份时创建普通实例。
- 同时重命名与归档时只递增一次版本；`createdCount/updatedCount` 正确。
- 两行名称互换不会串组。
- baseline 的版本变化、并发新增、并发删除和缺失实例均返回 409 且事务完全回滚。
- Administrator、Editor 与 Token-only Editor 权限沿用现状。

### Web

- 入口位置、文案和可访问名称正确，打开后继承父页面年份。
- 年度查询包含 `includeArchived=true`；加载、失败、重试状态正确。
- 同名、同月重复、系列与归档目标正确聚合；全年归档行仍显示；排序稳定。
- 没有数据时只有一个空白行；加号新增、减号仅移除新行并维持至少一个占位行。
- 新行名称/月度校验、名称唯一校验和无变化保存禁用正确。
- 单元格与改名生成正确批量载荷，不修改说明、关联或系列字段。
- 脏数据关闭和切年确认、保存成功返回状态、普通错误与 409 保留草稿/确认重载正确。
- 保存成功关闭弹窗、父页面年份更新且月份不变。

## 浏览器验收

使用一次性测试数据，不修改正式数据：

1. 从月目标页指定年份打开快速编辑，验证入口位置和年份继承。
2. 新增两行并跨多月勾选，保存后逐月核对实例。
3. 重开弹窗完成归档、恢复和整行改名，确认说明、工作计划关联及系列标识保持。
4. 验证未保存关闭/切年提示和冲突重载流程。
5. 在桌面与窄屏检查横向滚动、固定名称列、表头/底部操作区和弹窗纵向溢出。
6. 验收后清理一次性数据，并重新运行专项测试。

## 验收标准

1. 月目标页右上角出现“快速编辑”，并以全屏弹窗展示所选年份 1–12 月表格。
2. 表格准确聚合普通、归档、重复系列以及同名同月重复实例。
3. 勾选、新增、取消勾选、恢复和改名均符合 R2/R3，且不改变说明、计划关联或重复规则。
4. 保存是原子操作；并发变化不会产生部分写入或自动丢弃草稿。
5. 新行与同名校验明确，已有全年归档行可恢复，未保存导航有确认保护。
6. 窄屏可横向操作全部月份，名称列始终可见，可访问名称完整。
7. 专项测试、全量测试、类型检查、生产构建、浏览器验收与 `git diff --check` 全部通过。

## 范围外

- 编辑 Monthly Goal 的详细说明或 Goal-Plan Link。
- 创建、修改、停止或解散 Goal Recurrence。
- 把新增月份自动加入某个重复系列。
- 永久删除已有行或月目标实例。
- 跨年份批量改名或一次保存多个年份。
- 持久化年度行模板、行排序字段或独立行 ID。
- 数据库迁移、导入导出格式变化或新的权限模型。
