# Spec: 时间轴单指滑动切换时间范围

> Status: **已确认，待实施** — `grill-with-docs` 共识于 2026-09-12 确认；本文档及实施票据不代表代码已经交付。

## Goal

让触屏用户在工作计划时间轴中通过单指左右滑动，更快地浏览相邻时间范围：周视图按完整日历周切换，月视图按完整自然月切换。

本功能沿用 `CONTEXT.md` 中的 **Week View（周视图）** 与 **Month View（月视图）**，不引入新的业务领域对象。

## Confirmed decisions

| # | 决策 | 结论 |
| --- | --- | --- |
| D1 | 手势结果 | 周视图切换上/下一周；月视图切换上/下一月，不用左右滑动在周视图与月视图之间切换 |
| D2 | 输入设备 | 本期仅识别手机、平板上的单指触摸；不把触控板双指横滑或鼠标拖动解释为范围切换 |
| D3 | 生效区域 | 可从右侧时间轴的日期表头空白或网格背景开始；甘特条、拖拽手柄、提醒铃铛、浮层和工具栏控件不触发范围切换 |
| D4 | 月内滚动冲突 | 保留月视图的月内横向滚动；只有手势开始时已位于左或右边界，再向边界外滑动，才切换月份 |
| D5 | 方向与步数 | 左滑显示下一周/月，右滑显示上一周/月；一次手势最多切换一个时间范围 |
| D6 | 成立阈值 | 水平位移达到可见时间轴宽度的 15%，并钳制在 48–80 CSS px；水平位移至少为垂直位移的 1.5 倍，动作明显转为纵向时取消 |
| D7 | 过程反馈 | 边缘显示方向箭头和目标范围文案，强度随有效距离增加；甘特画布不跟随手指移动；减少动态效果模式仅显示静态提示 |
| D8 | 连续操作 | 一次手势只移动一步，成功触发后约 300ms 才接受下一次；数据仍在加载时允许继续逐次滑动，最终只呈现当前范围的数据 |
| D9 | 页面状态 | 普通模式与甘特图全屏模式均启用；抽屉、对话框或浮层打开时暂停识别 |
| D10 | 提交时机 | 松手时判断是否成立；松手前反向拉回到阈值以内则取消，不在移动过程中提前切换 |
| D11 | 月视图落点 | 保持时间连续性：进入下一月落在月初，进入上一月落在月末；手势和上一/下一范围按钮使用同一规则 |
| D12 | 加载显示 | 立即显示目标范围标题与日期网格，并覆盖明确的加载状态；不得把上一范围的 Work Plan 绘制到目标日期网格上 |
| D13 | 账户与空态 | Administrator、Editor、Viewer 均可使用；当前范围没有 Work Plan 时仍可滑动导航 |
| D14 | 页面上下文 | 保留视图、搜索、筛选、排序、全屏、列表展开状态和列宽；分页回到第一页、列表纵向滚动回到顶部，横向位置遵循 D11 |
| D15 | 浏览器边缘 | 从浏览器视口最左或最右约 24 CSS px 内开始的触摸留给浏览器原生后退/前进；应用手势必须从时间轴内部开始 |
| D16 | 中断规则 | 手势从头到尾必须保持单指；第二触点、系统取消、窗口失焦、指针捕获丢失或先形成纵向滚动意图时立即取消且不改变范围；仅在锁定为水平动作后抑制点击 |
| D17 | 查询失败 | 停留在已经切换到的目标范围，显示加载失败与重试入口，并允许继续滑动离开；不自动退回，也不显示旧范围数据 |

## Relevant existing behavior

- 现有“上一时间范围”“下一时间范围”按钮继续保留。
- 月视图画布在窄屏依赖横向滚动浏览同一个月内的日期。
- 甘特条已有点击打开、横向移动排期及两端拉伸调整日期等交互；日期网格已有双击新建工作计划行为。
- 当前月导航直接对锚点执行 `Date.setMonth(±1)`，月底可能溢出并跳过目标月份；实施时按钮与手势必须共用日历安全的逐月切换逻辑，才能满足 D1。

## Requirements

### R1 — 范围导航语义

- 周视图左滑进入下一完整日历周，右滑进入上一完整日历周；月视图左滑进入下一自然月，右滑进入上一自然月。
- 一次成立的手势只移动一个时间范围，不按距离或惯性一次跨越多个周或月。
- 手势与“上一时间范围”“下一时间范围”按钮共用同一套日历运算；月末、闰年和跨年导航不得因 JavaScript 日期溢出而跳过目标月份。
- 本功能不使用左右滑动在周视图与月视图之间切换。

### R2 — 输入设备、生效区域与页面状态

- 只识别单个触摸指针；鼠标拖动、触控板滚动、触控笔和非触摸 Pointer Event 不触发范围切换。
- 手势可从右侧时间轴的日期表头空白或日期网格背景开始。
- 从甘特条、调整手柄、提醒铃铛、按钮、工具栏控件、浮层或其他可交互元素开始的动作不得触发范围切换，并继续服从其既有交互。
- 普通布局和甘特图全屏模式均可使用；抽屉、对话框或任一浮层打开时暂停识别。
- Administrator、Editor、Viewer 均可使用；当前范围没有 Work Plan 时仍保留日期网格和滑动导航。
- 从浏览器视口左右各 24 CSS px 边缘内开始的触摸不由应用接管，保留浏览器原生后退、前进或系统边缘手势。

### R3 — 范围内横向滚动与边界交接

- 当前时间范围的画布存在横向滚动余量时，单指横向移动首先用于浏览范围内日期；这适用于月视图，也适用于极窄布局下可能产生横向余量的周视图。
- 只有手势开始时画布已经处于对应边界，且继续向边界外滑动，才成为范围切换候选：左边界右滑候选上一范围，右边界左滑候选下一范围。
- 画布没有横向滚动余量时视为同时位于左右边界，两种方向均可直接成为范围切换候选。
- 从范围内部开始的同一次滚动即使途中到达边界也不切换范围；用户须从边界开始新的手势，避免普通月内浏览在末端意外翻月。

### R4 — 成立、取消与反馈

- 有效水平距离为可见时间轴宽度的 15%，最低 48 CSS px、最高 80 CSS px；水平位移必须至少是垂直位移的 1.5 倍。
- 只有松手时仍满足阈值才提交导航；松手前反向拉回阈值内则取消。
- 动作明显先形成纵向意图时保持原生纵向滚动并取消候选；第二触点、系统 `pointercancel`、窗口失焦或指针捕获丢失也立即取消。
- 只有锁定为水平范围切换候选后，才抑制该动作产生的后续点击、双击或其他鼠标兼容事件。
- 候选过程中在对应边缘显示方向箭头及“上一周”“下一周”“上一月”或“下一月”，提示强度随有效距离增加；甘特画布本身不跟随手指位移。
- 系统启用减少动态效果时，反馈保持静态，不使用位移或渐变动画。
- 成功触发后约 300ms 内不接受下一次范围手势；间隔结束后即使数据仍在加载，也可再次逐步滑动。失效或取消的手势不启动该间隔。

### R5 — 新范围落点与页面上下文

- 周视图进入新范围时完整周通常铺满可见画布；若仍有横向余量，前进落在范围左端，后退落在范围右端。
- 月视图进入下一月落在月初，进入上一月落在月末；触摸手势和工具栏范围按钮遵循同一规则。
- 保留当前周/月视图、搜索词、状态与自定义字段筛选、显式排序、甘特全屏状态、工作内容列表展开状态、列表宽度及显示属性。
- 每次范围切换回到查询第一页，工作内容列表和甘特行的纵向位置回到顶部；不得把旧范围的游标页或纵向行位置套到新范围。
- 范围导航不改变 Work Plan、排期、提醒、筛选条件或任何服务端数据。

### R6 — 加载、连续导航与失败

- 导航提交后立即更新目标范围标题并渲染目标范围的日期网格，同时显示明确的“正在加载…”状态。
- TanStack Query 的占位数据不得作为目标范围成功数据处理；上一范围的 Work Plan 不得绘制在目标日期网格或列表中。
- 加载覆盖层仍允许符合 D8 的下一次范围手势；若用户连续逐步导航，只有当前最终范围对应的数据可以进入列表和甘特图，迟到响应不得覆盖它。
- 目标范围加载失败时停留在目标范围，保留标题和日期网格，显示“加载失败”及重试入口；用户仍可滑动或使用按钮离开。
- 重试成功后只呈现当前目标范围的数据，不恢复或混入先前范围的数据。

### R7 — 兼容性与无障碍替代

- 现有“上一时间范围”“今天”“下一时间范围”按钮全部保留，继续为键盘、鼠标、触控板和不使用手势的用户提供完整导航。
- 不改变甘特条点击打开、移动排期、两端拉伸、提醒铃铛、日期网格双击新建、列表与甘特纵向同步、全屏及 Viewer 权限语义。
- 不新增服务端 API、数据库字段、权限能力或持久化偏好。
- 手势反馈颜色只使用 `styles.css` 两套主题中的既有颜色令牌，浅色、深色和减少动态效果模式均须可辨识。

## Testing requirements

- 为日历安全的范围移动增加单元测试，覆盖周/月前后移动、月末（含 1 月 31 日与 3 月 31 日）、二月、闰年、跨年及前进/后退落点。
- 为手势判定增加单元测试，覆盖自适应 48–80px 阈值、1.5 倍纵横比、松手确认、反向撤销、300ms 间隔、第二触点及各类取消事件。
- 为横向滚动交接增加测试：范围内部正常滚动、从内部到达边界不翻页、从左边界右滑上一范围、从右边界左滑下一范围、无横向余量时双向可切换。
- 渲染测试覆盖日期表头空白、网格背景、空数据和加载覆盖层可以开始手势；甘特条、手柄、提醒铃铛、工具栏和浮层不能开始手势。
- 页面测试覆盖普通/全屏、Administrator/Editor/Viewer、抽屉或浮层打开、筛选/排序保留、分页与纵向滚动重置，以及前后月份的横向落点。
- 查询测试必须证明 placeholder 数据不会绘制为目标范围数据，快速连续导航只接纳最终范围响应，失败停留并可重试或继续导航。
- 回归测试覆盖鼠标、触控板等非触摸输入不触发范围切换，以及甘特条编辑、日期网格双击、纵向滚动和浏览器边缘保留区不受影响。
- 浏览器验收至少覆盖浅色/深色、约 390px 窄屏与平板宽度、周/月、列表展开/收起、普通/全屏、空数据、加载与失败状态；验证浏览器触摸仿真，并在具备设备条件时复核 iOS/Android 原生边缘手势。
- 实施后运行 Web 专项测试、根目录 `corepack pnpm typecheck`、`corepack pnpm test` 与 `corepack pnpm build`；非平凡代码改动须经过 `code-reviewer` 子代理审查并修复 P0/P1。

## Acceptance criteria

1. 触屏用户在周视图左滑进入下一周、右滑进入上一周；在月视图以相同方向逐月导航，一次只移动一步。
2. 月内横向滚动保持可用；只有从已有边界开始再次向外滑动并在松手时达到阈值才切换范围。
3. 日期表头空白、日期网格和空态可触发；甘特条、手柄、提醒、控件、抽屉、对话框和浮层不触发。
4. 有效阈值按可见宽度自适应至 48–80px，纵向动作、多指、系统取消和反向撤销均不误切范围。
5. 边缘方向反馈准确；甘特画布不随手拖动，减少动态效果模式无非必要动画。
6. 下一范围落左端、上一范围落右端；工具栏按钮与触摸手势一致，月底、二月、闰年和跨年均不跳错范围。
7. 导航保留视图、筛选、排序、全屏和列表布局，重置分页及纵向位置；不产生任何业务写入。
8. 加载时显示目标日期网格和明确状态，不展示旧范围 Work Plan；连续滑动只显示最终范围的数据。
9. 加载失败停留在目标范围，可重试，也可继续导航；不得自动退回或混入旧数据。
10. 所有账户和空数据范围均可用；鼠标、触控板、触控笔及浏览器最外侧 24px 原生手势不被接管。
11. 现有日期按钮、甘特条排期、提醒、双击新建、纵向滚动、全屏与权限行为无回归。
12. 相关测试、类型检查、构建与浏览器验收通过。

## Out of scope

- 用左右滑动在周视图与月视图之间切换。
- 鼠标拖拽、触控板双指、触控笔、键盘手势或多指手势导航。
- 跟手移动整张甘特画布、惯性连续翻页、一次跨越多个周/月或循环首尾范围。
- 抢占浏览器或操作系统的屏幕边缘返回/前进手势。
- 重新设计甘特条触摸排期、触屏长按新建、日期选择、触觉反馈或声音反馈。
- 修改 Work Plan、排期、提醒、查询契约、权限、数据库或服务端 API。
- 把手势设置、范围锚点或手势提示状态写入账户偏好或浏览器持久化存储。
