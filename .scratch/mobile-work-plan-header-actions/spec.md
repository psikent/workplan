# Spec: 手机端工作计划页头部操作布局

> Status: **已实现，浏览器验收待登录** — 已按用户批准的 D1–D5 完成代码与自动化验证；真实业务页视口验收需要已登录浏览器。

## Goal

在手机端把“标准工作计划”模板选择框和“导出 XLS”按钮移到“工作计划”标题的右上方，与标题保持同一行，从而减少顶部控件占用的纵向空间。

本需求只调整展示布局，不改变 Work Plan（工作计划）的数据、导出、模板、权限或交互语义。

## 已确认决策

- **D1 设备范围**：仅在手机断点 `<=720px` 生效；桌面端和其他非手机布局保持现状。
- **D2 同行布局**：页头左侧保留“工作计划”标题，右侧放置现有模板选择框与“导出 XLS”按钮；两项控件仍属于同一个页头操作组。
- **D3 窄屏策略**：在 `320–359px` 的窄屏上仍保持标题与两项控件同一行；模板名称允许被压缩或截断，但“导出 XLS”按钮必须保持可用。
- **D4 行为保护**：模板切换、导出属性弹层、管理员/编辑者/只读账户权限、禁用状态、键盘访问和导出请求均保持原行为。
- **D5 其他入口**：筛选栏中的搜索、状态、筛选、重置、排序和“新建工作计划/导入 XLS”控件不随本需求移动。

## Background facts

- `/work-plans` 页面由 `WorkPlansPage` 渲染。
- 当前页头已经包含标题和模板/导出操作组；移动端 CSS 将 `.page-header` 改为纵向布局，导致操作组位于标题下方。
- 模板选择框和“导出 XLS”按钮已有独立的语义、权限和测试覆盖。
- 本需求不引入新的领域概念；继续使用 `Work Plan`、`工作计划`、`工作内容` 和现有 XLS 导出术语。

## Requirements

### R1 手机端同行

- 在 `<=720px` 视口，页头标题和操作组必须处于同一视觉行。
- 标题位于左侧，操作组位于右侧并尽量右对齐。
- 操作组内仍按“模板选择框 → 导出 XLS 按钮”的顺序显示。
- 页头说明文字继续按现有移动端规则隐藏。

### R2 窄屏可用性

- 页面支持仓库现有最小 CSS 宽度 `320px`。
- 操作组不得因 flex 换行再次形成第二行。
- 空间不足时优先压缩模板选择框；模板名称可以省略显示，但模板选择控件仍可点击并保留完整选项。
- “导出 XLS”按钮、图标、可见焦点状态和点击区域不得被压缩到不可用。
- 页面不得因为该布局产生非预期的整页横向滚动。

### R3 非手机保护

- 桌面端和平板端保持现有页头布局、间距、控件宽度和操作组换行规则。
- 不移动、不隐藏、不复制筛选栏或其他工作计划操作。

### R4 行为和可访问性

- 选择或切换 XLS 模板的请求和状态不变。
- “导出 XLS”按钮的禁用条件、弹层打开/关闭、属性选择、另存为模板和导出请求不变。
- 现有 `select`、按钮名称、ARIA 属性、键盘焦点顺序和 Escape 关闭行为不变。
- 管理员、编辑者和 Viewer 的显示边界不变。

## Acceptance criteria

1. 在 390px（或相近常见手机宽度）视口，标题、模板选择框和“导出 XLS”按钮同处一行；操作组位于标题右侧。
2. 在 320px 和 360px 视口，页头不因这三个元素换成第二行；模板名称可截断，“导出 XLS”仍可见且可操作。
3. 手机端页头减少现有标题下方操作行占用的纵向空间，筛选栏和时间轴随之上移。
4. 桌面端回归现有布局，操作组仍位于页头右侧，其他工作计划控件位置不变。
5. 模板切换、打开/关闭“导出 XLS”弹层、导出和权限场景自动化测试无回归。
6. Web 类型检查、相关测试、构建和 `git diff --check` 通过；浏览器 QA 覆盖浅色/深色主题与 320/360/390px 视口。

## Out of scope

- 修改 XLS 文件内容、模板 schema、导出接口、筛选条件或导出排序。
- 修改 Work Plan 数据模型、权限模型、账户角色或服务端代码。
- 移动“新建工作计划/导入 XLS”拆分按钮或筛选栏内任何控件。
- 修改桌面端视觉布局。
- 为手机端新增横向滚动页头、长按手势或其他新交互。
