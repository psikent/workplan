# 03 — 工作计划抽屉月目标候选过滤
Type: task
Status: resolved
Blocked by: 01
Spec: ../spec.md
Scope: apps/web/src/components/WorkPlanDrawer.tsx、apps/web/src/components/WorkPlanDrawer.test.tsx

## 背景

规格 R1/R4。工作计划抽屉当前展示所有非归档月目标。用户已确认抽屉应按计划覆盖月份筛选：跨月计划可选多个对应月份目标，修改日期后立即移除越界选择。

## 改动清单

1. 使用草稿 `startAt/endAt` 和 `rangeOverlapsMonth` 派生符合范围的月目标，保留现有年月/创建时间排序。
2. 候选规则应用于新建和编辑抽屉；新建计划使用当前默认日期或 `initialDate` 生成的草稿范围。
3. 封装开始/结束时间更新：
   - 先更新对应输入值；
   - 仅在新范围可解析且 `endAt > startAt` 时清理 `monthlyGoalIds`；
   - 保留与新范围任一月份重叠的目标，移除其余目标；
   - 日期暂时无效时不清理，继续由现有提交校验处理。
4. 初次打开时，将历史越界已选目标保留在列表中，标记“当前关联，不在计划覆盖月份”；未选中的越界目标不得出现。
5. 一旦用户提交有效日期变化，历史越界目标也按新范围清理；随后改回日期不自动恢复。
6. 没有候选项且没有历史当前关联时，仍渲染“月目标”区块并显示“计划覆盖月份内暂无可关联月目标”。
7. 冲突提示中的“其他工作任务”改为“其他工作计划”。
8. 不改变保存载荷结构、重复计划行为、自定义字段、状态或其他抽屉布局。

## 验收

- 单月计划只显示对应月份目标。
- 跨月、跨年计划显示所有实际覆盖月份目标，不显示范围外目标。
- 日期形成新的有效范围后，越界目标立即取消选择并从最终载荷移除。
- 无效的临时日期输入不会误删关联。
- 未修改日期时，历史越界关联保留并清晰标识。
- 抽屉其他控件和布局无回归。

## Answer

- 工作计划抽屉按草稿时间范围筛选并排序月目标，新建默认日期、`initialDate`、编辑日期及跨月跨年范围均复用 `rangeOverlapsMonth`。
- 日期输入只有在形成有效正向范围后才清理越界关联；无效临时输入会保留选择，保存载荷只包含清理后仍关联或候选响应无法判定的目标 ID。
- 历史越界关联初次打开时继续显示、保持勾选并标记“当前关联，不在计划覆盖月份”，有效日期变化清除后不会自动恢复。
- 月目标区块始终保留并提供覆盖月份空状态，占用冲突提示已统一为“其他工作计划”；组件专项测试、类型检查、生产构建和仓库完整测试均通过。

## Comments

- 用户确认工作计划侧使用“计划覆盖月份”，不是开始月份或系统当前月份。
