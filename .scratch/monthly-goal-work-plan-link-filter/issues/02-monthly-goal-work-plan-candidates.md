# 02 — 月目标页面关联计划候选过滤
Type: task
Status: ready-for-agent
Blocked by: 01
Spec: ../spec.md
Scope: apps/web/src/pages/MonthlyGoalsPage.tsx、apps/web/src/pages/MonthlyGoalsPage.test.tsx

## 背景

规格 R1/R3。当前月目标新建、编辑和快捷关联入口都会展示完整工作计划列表，并使用“关联任务”文案。三个入口必须采用同一月份规则，同时保留首次打开时的历史越界关联。

## 改动清单

1. 基于 `rangeOverlapsMonth` 派生两个候选集合：
   - 表单候选：使用草稿 `year/month`；
   - 快捷弹窗候选：使用 `linkingGoal.year/month`。
2. 保留现有计划排序；快捷弹窗的标题/说明搜索在月份过滤之后执行。
3. 年份或月份控件变化时：
   - 先生成新草稿月份；
   - 当前 `workPlanId` 不再重叠则设置为空；
   - 仍重叠则保留；
   - 清空只更新草稿，保存时才提交解绑。
4. 初次打开编辑表单时，将历史越界当前计划保留在选择器中，文案标记“当前关联，不在所选月份”；其他越界计划不得进入候选。
5. 快捷弹窗保留历史越界的“当前关联”区域并增加“不在目标所属月份”提示，候选列表仍只含当月计划。
6. 没有候选计划时显示“所选月份暂无可关联计划”。
7. 将页面说明、列表表头、按钮 title/aria-label、表单标签、未关联提示和重复周期提示中的“任务”统一为“计划”。
8. 不改变 API 调用、保存 mutation、版本冲突、归档、删除或重复系列行为。

## 验收

- 新建、编辑和快捷弹窗均只提供目标月份内的计划。
- 跨月计划在其每个实际覆盖月份都可选。
- 改年月后越界关联立即从草稿清空，取消编辑不会改变服务端数据。
- 历史越界关联在未改年月时继续显示和保存。
- 搜索不会重新引入其他月份计划。
- 月目标关联区域不再出现“关联任务”“未关联任务”或“工作任务”。

## Comments

- 用户确认文案替换覆盖月目标页面全部关联入口，而非仅新增/编辑表单。
