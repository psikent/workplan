# 待实现规格：月目标与工作计划按月份关联

## 目标

统一月目标关联区域的领域语言，并限制关联候选项只显示时间上相关的数据：

- 月目标侧只列出与该目标所属月份有时间重叠的工作计划。
- 工作计划侧只列出与该计划时间范围有重叠的月目标。
- 用户修改月份或计划日期时，表单立即移除不再符合范围的关联。
- 打开已有数据时不主动清理历史越界关联，避免仅查看或编辑其他字段就丢失关系。

本规格只改变 Web 界面的候选项与关联文案，不新增服务端约束，不修改 API、数据库或共享契约。

## 已确认的产品决策

1. 月目标页面所有相关位置统一使用“关联计划”，不只修改新建和编辑表单。
2. “当月工作计划”按时间范围是否与目标月份有任何重叠判定，而不是只看开始日期。
3. 月目标的年份或月份改变后，当前关联若不再重叠，在表单中立即清空；用户保存后才持久化解绑。
4. 月目标列表快捷关联入口采用相同的月份筛选规则。
5. 工作计划详情抽屉只显示计划覆盖月份内的月目标；跨月计划可以关联多个对应月份的月目标。
6. 工作计划日期变化后，已选月目标若不再重叠，在表单中立即取消选择；用户保存后才持久化解绑。
7. 打开表单时发现历史越界关联，不立即解除；只有用户修改对应的月份或日期后才按新范围清理。
8. 候选项过滤在前端完成；外部 API 客户端仍可提交跨月份关联。

## 领域语言

沿用 `CONTEXT.md` 的 **Work Plan** 与 **Monthly Goal**，并使用以下关联术语：

| 术语 | 含义 | 避免使用 |
| --- | --- | --- |
| 目标计划关联（Goal-Plan Link） | 一个 月目标 与一个 工作计划 之间的受约束关联；一个月目标至多关联一个工作计划，一个工作计划可关联多个月目标 | Task-Goal Tag、目标任务标签、关联任务 |
| 关联计划 | 月目标页面中用于选择或显示关联 Work Plan 的用户界面名称 | 关联任务 |

该术语变化同步到 `CONTEXT.md`。这是可逆的语言和界面规则调整，不满足 ADR 的必要条件，因此不新增 ADR。

## 当前实现事实

- `MonthlyGoalsPage` 通过 `/work-plans?limit=500` 获取工作计划，当前在新建/编辑选择器和快捷关联弹窗中直接使用完整列表。
- `WorkPlanDrawer` 从 `WorkPlansPage` 接收完整的非归档月目标列表，当前按年月倒序展示，不按计划时间过滤。
- 工作计划有 `startAt` 与 `endAt`；月目标有 `year` 与 `month`。
- 月目标关联关系的服务端基数约束保持不变：一个月目标至多属于一个工作计划，一个工作计划可带多个 `monthlyGoalIds`。
- 现有表单均在用户点击保存时提交数据，因此“立即解除”是立即更新表单状态，服务端关系在保存成功后改变。

## R1 — 关联文案统一

月目标关联区域的用户可见文案统一使用“计划”：

- 页面说明中的“关联任务”改为“关联计划”。
- 列表表头、图标按钮标题与可访问名称改为“关联计划”。
- 新建/编辑表单字段名改为“关联计划”。
- “未关联任务时”改为“未关联计划时”。
- 重复周期提示中的“每期可单独编辑与关联任务”改为“每期可单独编辑与关联计划”。
- 工作计划抽屉中的冲突提示改为“该目标已关联其他工作计划”。
- 服务端关联冲突文案改为“月目标「…」已关联其他工作计划”，错误代码和详情结构保持不变。

只核查运行时代码、活动测试和当前领域文档；不改写已解决票据中的历史讨论记录。

## R2 — 月份重叠规则

月份采用本地日历边界形成半开区间：

```text
[当月第一天 00:00, 下月第一天 00:00)
```

工作计划与月份重叠，当且仅当：

```text
计划开始时间 < 下月第一天 00:00
且
计划结束时间 > 当月第一天 00:00
```

边界语义：

- 计划跨过月初或月末时，属于其实际覆盖的每个月份。
- 计划恰好在某月第一天 00:00 结束，不属于该月。
- 计划恰好在下月第一天 00:00 开始，不属于前一个月。
- 跨年月份使用相同规则。
- 日期无法解析或 `endAt <= startAt` 时，不产生新的候选匹配，也不据此清理已有选择。

新增共享纯函数 `rangeOverlapsMonth(startAt, endAt, year, month)`，由两侧界面复用，避免出现两套月份判定。

## R3 — 月目标页面候选工作计划

### 新建与编辑表单

- 根据草稿中的 `year/month` 过滤工作计划，再沿用现有开始时间排序。
- 新建表单默认使用当前页面选中的年月。
- 编辑表单默认使用目标自身年月。
- 年份或月份变化时，若当前 `workPlanId` 不再重叠，立即清空表单选择。
- 清空只是草稿状态变化；用户取消编辑时不改变服务端数据，保存时提交 `workPlanId: null`。

### 历史越界关联

- 初次打开编辑表单时，若当前关联计划不在目标月份，仍将其作为当前选项显示。
- 选项增加“当前关联，不在所选月份”提示，但不作为其他目标可选的越界候选。
- 用户只修改标题、说明等字段并保存时，保留该关联。
- 用户修改年份或月份后，重新应用月份规则；不符合新范围的当前关联立即清空，即使随后把月份改回也不自动恢复。

### 列表快捷关联弹窗

- 使用正在关联的月目标自身 `year/month` 过滤工作计划。
- 文本搜索在月份过滤之后执行，只搜索当月候选的标题和说明。
- 当前历史越界关联继续显示在“当前关联”区域，并标注“不在目标所属月份”；其他越界计划不进入候选列表。
- 无候选项时显示“所选月份暂无可关联计划”。

## R4 — 工作计划抽屉候选月目标

- 根据抽屉草稿中的 `startAt/endAt`，列出所有月份与该时间范围重叠的月目标。
- 单月计划只显示该月目标；跨月或跨年计划显示每个覆盖月份的目标。
- 保留现有年月倒序、创建时间升序的排序规则。
- 开始或结束时间变化并形成有效范围后，立即从 `monthlyGoalIds` 中移除不再重叠的目标。
- 日期输入暂时无效或结束时间不晚于开始时间时，不清理选择，继续由现有提交校验显示错误。
- 初次打开时的历史越界已选目标继续显示，并标注“当前关联，不在计划覆盖月份”。
- 用户修改有效日期范围后，所有不再重叠的已选目标都被移除；即使随后改回原日期也不自动恢复。
- 没有候选项且没有历史当前关联时，保留“月目标”区块并显示“计划覆盖月份内暂无可关联月目标”。

## R5 — 数据流与兼容性

- 月目标页面继续复用现有工作计划查询，不新增按月份查询的 API。
- 工作计划页面继续复用现有月目标查询，不新增按范围查询的 API。
- 不修改 `MonthlyGoal`、`WorkPlan`、创建/更新请求或响应类型。
- 不新增数据库迁移，也不批量清理历史关联。
- 不在服务端强制月份重叠；API、导入和旧客户端创建的越界关联仍可存在，并按 R3/R4 的历史数据规则展示。
- 权限、归档、重复周期、关联基数、乐观锁、现有查询上限和排序语义保持不变。

## R6 — 测试要求

### 共享规则

- 同月计划匹配。
- 跨月、跨年计划匹配每个实际覆盖月份。
- 月初/月末相等边界不产生零长度重叠。
- 无效日期和反向日期不匹配。

### MonthlyGoalsPage

- 新建、编辑和快捷弹窗只显示目标月份内的工作计划。
- 搜索不会重新引入其他月份计划。
- 改年份或月份立即清除越界关联；仍重叠的关联保留。
- 初次打开时的历史越界关联保留，修改非日期字段不会解绑。
- 新文案、可访问名称、历史提示和空状态正确。

### WorkPlanDrawer

- 单月计划只显示同月目标。
- 跨月和跨年计划显示所有覆盖月份目标。
- 修改有效日期范围立即移除越界目标。
- 暂时无效的日期输入不会误删选择。
- 初次打开时的历史越界关联保留。
- 保存载荷只包含清理后的 `monthlyGoalIds`。

## 验收标准

1. 月目标关联区域不再使用“关联任务”或“工作任务”指代 Work Plan。
2. 月目标侧所有关联入口只提供与目标所属月份重叠的工作计划。
3. 工作计划抽屉只提供与计划时间范围重叠的月目标，跨月计划可见多个对应月份。
4. 修改月份或有效计划日期后，表单立即移除越界关联；保存后服务端关系同步更新。
5. 仅打开历史越界数据不会导致关系丢失，且界面明确标识该例外。
6. API、数据库和共享契约无结构变化，既有非关联行为不受影响。
7. 专项测试、Web 全量测试、Server 全量测试、类型检查、构建与差异检查全部通过。

## 范围外

- 服务端强制月份一致性或新增验证错误。
- 自动迁移、自动清理或批量修复历史越界关联。
- 修改工作计划/月目标关联基数。
- 改造现有查询分页或 500 条工作计划加载上限。
- 修改归档目标、重复系列、导入导出或权限行为。
- 重写已解决的 `.scratch/monthly-goals` 历史票据和讨论。
